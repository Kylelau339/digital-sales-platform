# M3 API

All endpoints are under `/api/v1`. State-changing requests require the signed session cookie, exact `Origin`, and `X-CSRF-Token`. Admin endpoints require the `admin` role. Seller earnings requires a verified `seller`.

## Buyer complaints

### `GET /complaints`

Returns complaints belonging to the authenticated buyer.

### `POST /complaints`

Requires `Idempotency-Key` (8–128 characters).

```json
{
  "orderId": "order_...",
  "entitlementId": "ent_...",
  "reason": "materially_not_as_described",
  "description": "The delivered package differs from the listing."
}
```

Refund-eligible reasons are subject to the order's frozen 7-day window. Rights, malware, trademark, unauthorized-distribution, misleading-license, and other reasons are always accepted for manual review.

## Admin complaints

### `GET /admin/complaints?status=&limit=&offset=`

Returns complaints with order, buyer email, seller, template name, download count, and the latest refund request.

### `GET /admin/complaints/:id`

Returns the complaint, order, payment transaction, entitlements, refund requests, and the refund-policy evaluation (`eligible`, `blockers`, `fullRefundCents`).

### `POST /admin/complaints/:id/refund/approve`

Requires `Idempotency-Key`.

```json
{
  "amountUsdCents": 11000,
  "reason": "Policy and evidence confirmed."
}
```

M3 only accepts the full amount returned in `evaluation.fullRefundCents` (subtotal plus recorded tax). The API calls Stripe Refund with idempotency key `refund:<complaintId>`, writes the refund ledger, marks the order refunded, resolves the complaint, revokes entitlements, and appends the audit log.

### `POST /admin/complaints/:id/refund/reject`

Requires `Idempotency-Key`.

```json
{ "reason": "This is a rights dispute, not a refund." }
```

## Takedown

### `POST /admin/templates/:id/takedown`

Requires `Idempotency-Key`.

```json
{ "mode": "suspend", "reason": "Rights evidence under review." }
```

- `suspend` moves `approved` to `suspended`. New checkout and existing downloads are blocked by the existing guards. Re-approval can restore the listing.
- `remove` is terminal, clears the current version, and revokes all entitlements for the template.

### `GET /admin/templates?status=approved`

Lists templates available for takedown.

### `GET /admin/audit?limit=&offset=`

Returns the append-only audit log.

## Seller earnings

### `GET /seller/earnings?from=YYYY-MM-DD&to=YYYY-MM-DD`

Returns:

- `summary`: `grossSalesCents`, `platformFeeCents`, `refundsCents`, `netEarningsCents`, `taxCollectedCents`, `orderCount`, `unitCount`.
- `series`: per-day sales and refunds.
- `templates`: per-product totals.
- `recentOrders`: latest orders in the range.

The range is limited to 366 days. Tax is excluded from seller revenue. Refunds are attributed to the date the refund succeeded and reduce net earnings by the seller reversal amount.

## Stripe webhook

`POST /webhooks/stripe` handles both Checkout and Refund events. Refund events are `refund.created`, `refund.updated`, and `refund.failed`. The route verifies the raw body signature and deduplicates events with `payment_event_inbox`.
