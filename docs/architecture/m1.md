# M1 Implementation Notes

M1 is limited to seller package intake, worker scanning, license parsing, proof evidence, preview-image review, and the moderation review queue. Payment, downloads, refunds, takedown transactions, video processing, scheduled URL rechecks, and full antivirus scanning remain out of scope.

## Version and review target

`TemplateVersion.status` has four values:

```text
draft -> pending_license_review -> approved | rejected
```

`removed` is product-level only. A removed product keeps historical version records, but `currentVersionId` must be null and cannot point to a removed product's approved version.

`TemplateProduct.reviewTargetVersionId` is a single nullable field. The review queue filters by this field, not by product status. Submitting a version replaces the previous target and invalidates the old review. Approve, reject, and request-changes clear the field.

`request-changes` always creates a new `TemplateVersion`. If the previous version was never approved, the product returns to `draft` with `currentVersionId=null`. If an approved version is currently sold, it stays approved and remains the current version while the new version is independently reviewed.

`currentVersionId` changes only inside the approve transaction after all blockers and revision checks pass.

## Revision gate

`TemplateVersion`, `LicenseProof`, and `PreviewAsset` each carry an integer `revision`. Every write increments the corresponding revision. Approve captures revisions before external hash verification, then compares them again inside the short transaction. A mismatch returns `REVIEW_BLOCKERS_PRESENT` and does not change product/version state.

All queue responses, approve validation, and frontend disabled state use the same pure `deriveBlockers(review)` function.

## Scan and parser separation

ZIP structure and safety determine `scanStatus`:

- readable, safe, structurally valid package: `passed`;
- unreadable/extraction failure/security rejection: `failed`;
- timeout: `timed_out`.

For `.motion`, `motion.json` is required. A plain `.zip` is not required to contain `motion.json`.

A package must contain at least one permitted license source: `licenses/`, `TEMPLATE-LICENSE.txt`, a README `## License`/`## Licensing` section, or an `asset-manifest.json` non-empty `license` field. Otherwise `LICENSE_FILE_MISSING` makes `scanStatus=failed`.

License semantics are separate:

- contradictory statements: `parserStatus=failed`, `conflictFlag=true`;
- no match or a critical semantic field unknown: `parserStatus=unknown`, manual review;
- all `commercialUse`, `sourceRedistribution`, and `derivativeResale` have explicit conclusions: `parserStatus=parsed`.

A ruleset update does not automatically rescan approved versions. Whole-site reassessment is a later M3 decision.

## Capture evidence

M1 does not take screenshots. `screenshotSha256` remains null. Proof capture retains:

```text
capturedAt
finalUrl
sourceDomain
pageSummary (max 2000 chars)
title
h1
responseSha256
screenshotSha256 = null
```

HTML normalization removes script/style content, collapses whitespace, and truncates visible text. URL capture is limited to three attempts per version per minute; failures count. When a capture completes, the prior active capture becomes `superseded` and the new capture becomes active, regardless of success or failure. The fourth request is rejected without creating a new capture. Historical capture outcomes remain visible to reviewers.

`PROOF_URL_NOT_AUTHORITATIVE` is returned by capture only. Review endpoints use the stored capture and authority decision.

## Upload safety

Proof files accept PDF/PNG/JPEG and are limited to 10 MB. Preview files accept JPEG/PNG/WebP, are limited to 10 MB and 4096x4096, and must be re-encoded without EXIF before public use. Reviewer responses use `X-Content-Type-Options: nosniff`; PDFs are served as attachment. Video upload is rejected before multipart parsing with `VIDEO_UPLOAD_NOT_SUPPORTED`.

M1 scanner defaults:

```text
archive: 20 MiB
expanded: 200 MiB
entries: 5000
single file: 50 MiB
worker timeout: 5 seconds
worker concurrency: 2
```

Timeout always terminates the worker and removes the temporary extraction directory in `finally`. The scanner never executes package code. It performs basic feature checks only, not full antivirus scanning.
