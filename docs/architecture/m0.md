# M0 架构边界

## 分层

```text
React UI
  -> HTTP client / fixture adapter (local only)
  -> Fastify routes + request validation
  -> application use cases
  -> repository ports
  -> Kysely SQLite adapter
  -> SQLite WAL
```

M0 的业务写事务只在 repository/UnitOfWork 内执行本地数据库操作。外部 HTTP、支付、邮件、URL 证据抓取、对象存储签名和未来扫描任务均不得在事务内发生。

## 单一来源约定

- `TemplateVersion.packageLicense.parserStatus` 是 parserStatus 的唯一来源；不建 `template_versions.parserStatus` 双写列。
- `template_files` 按 `TemplateVersion.files[]` 建表，但 M0 不提供 TemplateFileRepository。
- `Complaint.timeline` 使用规范化时间线记录；避免 JSON 字段和子表双写。
- `LicenseProof.previewAssetLicenseSummary` 是由 PreviewAsset 授权记录派生的审核投影，客户端不能在创建 proof 时伪造它。
- RefundPolicy 内容按版本不可变；只允许在短事务中切换 `isActive`。
- API 对外只返回 `approved`，前端在本地化层显示“已上架 / Live”。

## M0 状态边界

M0 建立状态枚举、状态转换和资格守卫，但不执行后续里程碑动作：

- 不解压或扫描 `.motion` 包。
- 不创建真实上传 finalize、下载签名 URL 或支付 webhook 路由。
- 不执行退款、投诉下架、重新签发授权或真实邮件。
- `reissued` entitlement 在买家列表保留，但下载资格守卫拒绝。

## 安全边界

- Session Cookie 是签名、HttpOnly、SameSite=Strict 的 opaque ID。
- `auth_sessions.csrfTokenHash` 保存每个 session 当前唯一 token 的 hash。
- 所有 Cookie Session 写请求要求精确 Origin 和 `X-CSRF-Token`；管理员不能绕过。
- M0 的 `USE_FIXTURES` 只允许本地开发/测试，生产启动和生产构建均拒绝。
- 预览、proof、投诉证据和模板文件不放入公开静态目录。
